# Metallic Studios — Public Status Website Prototype

**Source:** \`docs/site/index.html\`, \`styles.css\`, \`app.js\`. This is a real HTML/CSS/JS static site, not a screenshot/mockup.
**Status:** Version-controlled prototype, **not deployed**, no download yet.

## View locally

From a working copy of this repository, serve the repository root:

\`\`\`bash
python -m http.server 8000 --bind 127.0.0.1
\`\`\`

Then open \`http://127.0.0.1:8000/docs/site/\`. The page fetches \`../progress.json\`, generated by the [issue workflow](../../.github/workflows/update-progress.yml). Opening \`index.html\` directly through a \`file:\` URL may trigger fetch restrictions; serve it over localhost to test the real data.

## Design evidence and principles

- [Design system](../DESIGN_SYSTEM.md): Obsidian Alloy dark charcoal/titanium/plum colors, deliberately asymmetric hero typography, reduced-motion option, accessibility and visual QA.
- The progress meter is **purely** GitHub closed/open phase-tagged issues; it must not present “users online” or working game builds.
- Data is read from the generated *sanitized aggregate* \`progress.json\`; no GitHub authorization token or arbitrary private issue body is embedded.
- No fake gameplay screenshots, fictitious live players, or inert download buttons.
- Every live link goes to existing project documentation/issues. Links to private GitHub resources work only for authenticated authorized collaborators.

## Publication options (not executed)

Repository \`oncoursemail/Metallic\` is **private**. [GitHub Pages documentation](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site) states that publishing Pages from private repositories requires an eligible plan; publishing a public Pages site from a private repository can make its **website contents public**. Avoid exposing any sensitive internal assets, secret configuration or case reports.

This prototype lives at \`docs/site\`, but \`docs/site\` is **not** a selectable direct GitHub Pages publishing root when using a branch folder source. A future deployment workflow should publish a purpose-built \`_site\` artifact containing only:
- \`index.html\`, \`styles.css\`, \`app.js\`;
- sanitized and reviewed \`progress.json\` **at its expected relative location** (website root needs path adjustment or rewrite for \`../progress.json\`);
- optional approved static original branding assets.

Alternatively, create a separate public \`Metallic-Web\` project and copy reviewed files + counts with a tokenless deploy, or use a static website host. **Do not make this private game/backend repository public solely to make the progress website work.**
