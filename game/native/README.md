# Metallic-RC — Metallic Meadow native playtest

This directory contains a playable native desktop experiment for **Metallic-RC**: an original meadow with walking and jumping, an authored community barn, shared trail markers, a community bell, live multiplayer visitors, and a watch map. It uses **Godot 4.5.2** and the Compatibility renderer. The production engine and VR architecture remain open decisions; see [the experiment ADR](../../docs/ADR_NATIVE_PLAYTEST.md).

The private playtest has a **32-player admission limit**. That is a configured limit, not a claim of measured Internet capacity, device performance, or production readiness. Test results belong to the accompanying verification receipt for the specific source commit and build hashes.

## Play an exported desktop build

Extract the complete Windows or Linux archive. Keep the executable and matching `.pck` file in the same directory. Open `Metallic-RC.exe` on Windows or `Metallic-RC.x86_64` on Linux.

1. Enter a name containing 2–20 ASCII letters, numbers, spaces, hyphens, or underscores. Start with a letter or number.
2. Select **Host meadow** to start a local authority and join it as a real player. The initial host is counted as one visitor.
3. For a second player on the same computer, open another instance, enter a different display name, leave the address as `127.0.0.1` and the port as `27841`, and select **Join address**.
4. For a private LAN session, the host can enable **Allow LAN players when hosting**. Other players enter that computer's LAN IP in the address field and the same port. The host's firewall must permit the chosen UDP port. The checkbox binds to `0.0.0.0`; it does not set up router forwarding or Internet hosting.

Find the three trail markers beside **Canopy trail**, **The orchard**, and **The little green**. Press **E** near each marker. Discoveries are shared by everyone in the meadow. After all three are lit, enter the barn through its open doors and press **E** by the hanging bell. The completed round resets after 30 seconds. A local host can also start another round from the pause menu.

The golf lane and treehouse are scenery in this playtest. There is no golf simulation, climbing system, or building editor in this directory.

## Controls

| Control | Action |
| --- | --- |
| WASD or arrow keys | Move relative to the camera |
| Mouse | Look around while the cursor is captured |
| Mouse wheel | Adjust third-person camera distance |
| Space | Jump |
| E | Interact with a nearby trail marker or the barn bell |
| Tab | Open or close the meadow watch |
| Esc | Open pause/settings, or return from an overlay |
| F8 | Save a screenshot to `user://meadow-screenshot.png` |

The watch plots the actual session's player positions and discoveries. It shows connected visitors, up to six names, and an accurate count of additional visitors. Opening an overlay stops your movement input and releases the mouse. The shared server continues running while a player has a menu open.

### Settings and accessibility

**Settings** is available before joining and in the pause menu. Bell volume, mouse sensitivity, and reduced decorative motion are saved to `user://meadow-settings.cfg` when changed.

Reduced decorative motion starts **on**. Camera shake is absent. Walking and jumping animations stay active so movement remains readable. No microphone, voice service, or external audio account is used. The bell is an original synthesized sound generated by `main.gd`.

Godot's default `user://` location for this project is normally:

- Windows: `%APPDATA%\Godot\app_userdata\Metallic-RC\`
- Linux: `$XDG_DATA_HOME/godot/app_userdata/Metallic-RC/`, or `~/.local/share/godot/app_userdata/Metallic-RC/` when `XDG_DATA_HOME` is unset.

These paths can differ if the runtime environment supplies alternate user-data settings.

## Run from source

Use the pinned official **4.5.2 stable** Godot editor, version string `4.5.2.stable.official.6ce3de25a`. Run these commands from the repository root; `godot` denotes that executable on your PATH.

```sh
# Import the project and validate script loading.
godot --headless --editor --path game/native --import --quit

# Open the title screen.
godot --path game/native

# Open a local authority and a real local player directly.
godot --path game/native -- --host --name Alex --port 27841

# Open a second client against that authority.
godot --path game/native -- --connect 127.0.0.1 --port 27841 --name Visitor
```

Engine arguments precede the standalone `--` separator. Metallic-RC arguments follow it. In particular, Metallic-RC's `--quit-after` takes **seconds**, while Godot's engine argument with the same spelling has different semantics. Keep it after `--`.

## Dedicated server and saved activity

A source server uses the same authoritative simulation without constructing the environment, HUD, camera, visitors, or bell audio:

```sh
godot --headless --path game/native -- --server --bind 127.0.0.1 --port 27841 --state-file /absolute/private/path/meadow.json
```

The exported **Linux Server** preset includes the `dedicated_server` feature and starts as a server automatically. Its explicit equivalent is:

```sh
./Metallic-RC-Server.x86_64 --headless -- --server --bind 127.0.0.1 --port 27841 --state-file /absolute/private/path/meadow.json
```

A dedicated server occupies no player slot. Desktop clients join using **Join address** or `--connect`. A listen host, started with **Host meadow** or `--host`, is also a player.

Default hosting binds only to loopback. Choose a specific private address or `0.0.0.0` deliberately when a private remote playtest needs it. The current transport is for trusted private testing: it supplies neither account authentication nor encrypted public session admission.

`--state-file` is optional. When supplied to a host or server, it saves the activity's round and discovered markers when progress changes. Successful replacement uses a same-directory temporary file and rename; invalid or unreadable saved state is preserved and prevents startup. Omitting the flag leaves activity progress in memory. This mechanism is one current save, not a history of backups or a power-loss durability guarantee.

Player identities, positions, and short-lived reconnect credentials are not restored from that activity save. Brief disconnects can resume against the same running authority within the current 120-second reservation window. The client attempts bounded reconnection automatically and shows its actual status. A server restart creates fresh player identities while valid saved activity can be restored. Use **Reconnect to meadow** when offered, or leave and join again after retry attempts end.

## Command-line reference

| User argument, after `--` | Effect |
| --- | --- |
| `--host` | Start a listen host and local player |
| `--server` | Start authority only, with no graphical scene construction |
| `--connect ADDRESS` | Join a known server; use `--port` separately |
| `--bind IP` | Numeric authority bind address; default `127.0.0.1` |
| `--port NUMBER` | UDP port, 1024–65535; default `27841` |
| `--name NAME` | Local display name; default `Traveler` |
| `--state-file PATH` | Opt into saved activity on the authority |
| `--snapshot-file PATH` | Write an inspection-only JSON snapshot every half-second and at exit |
| `--screenshot PATH` | Save a rendered viewport PNG after 2.2 seconds; requires a graphical display |
| `--overview` | Use the fixed overview camera while joined |
| `--watch` | Open the real watch overlay after joining |
| `--pause` | Open settings after joining |
| `--quit-after SECONDS` | Leave and exit after the chosen duration |

Screenshot and snapshot parent directories should already exist. `--snapshot-file` is a diagnostic export and does not restore a game. Its purpose differs from `--state-file`.

For a reproducible rendered inspection:

```sh
godot --path game/native -- --host --name Tester --port 27842 --overview --screenshot /absolute/path/overview.png --quit-after 5
```

## Export Windows, Linux, and Linux Server builds

The repository build helper uses a temporary project copy, the pinned editor, and separately supplied official matching export templates. It records source revision, dirty-state labeling, source digest, template digest, artifact hashes, and notices. It does not publish or sign a release.

```sh
python3 scripts/build_native.py --godot /absolute/path/to/godot --templates /absolute/path/to/templates --output /absolute/path/to/fresh-build --target all
```

The templates directory must contain `linux_release.x86_64` and `windows_release_x86_64.exe`. A normal build requires committed source. Use `--allow-dirty` only for an explicitly labeled developer build. The helper refuses to replace an existing target folder; choose a fresh output directory.

Keep `BUILD.json`, the packaged notices, executable, and `.pck` together when distributing a private build. Compare evidence using the recorded commit and digests. An export existing on disk is distinct from that export passing a target-device playtest.

## Verification and code boundaries

```sh
godot --headless --path game/native --script res://tests/test_simulation.gd
python3 game/native/tests/run_network_tests.py --godot /absolute/path/to/godot --output /absolute/path/to/test-evidence
```

The tests exercise the pure simulation and real ENet processes. Rendering, keyboard/mouse interaction, exported binaries, reconnection behavior, and target hardware require their own recorded verification. Do not turn the configured player cap into a benchmark claim.

| File | Responsibility |
| --- | --- |
| `scripts/main.gd` | Desktop input/camera, startup flags, client orchestration, screenshots and bell audio |
| `scripts/meadow.gd` | Authored static visual environment and landmark presentation |
| `scripts/avatar.gd` | Original articulated visitor mesh and movement animation |
| `scripts/hud.gd` | Title/host/join flow, live watch, session state and settings |
| `scripts/session.gd` | ENet transport, admission, reconnection, snapshots and saved activity |
| `scripts/simulation.gd` | Fixed-step authority, movement, interaction and shared round rules |
| `scripts/world_data.gd` | Shared positions, collision bounds, markers and spawn locations |

This playtest demonstrates a small desktop gameplay loop. The broader Metallic-RC roadmap still includes a production engine decision, VR, accounts, spatial voice, social graph, room discovery, creator tools, launcher delivery, moderation, signed distribution, and public infrastructure. The prototype does not establish those systems as delivered.
